## go mod 模块和包

### init & run

`go mod init name` 初始化当前目录为一个模块，会自动创建 `go.mod`，写入 `module name` 和语言版本，这个 name 也是这个模块下跨包引用时 import 的根目录，**模块名 + 相对路径 import 模块下的任意包**

`go run .` 启动会找当前目录下的可执行文件进行执行，包名是 main 且有 `main()` 函数，且没有参数和返回值，才会被当成可执行文件

库包则习惯上和目录名一致
一个目录下只能有一个包（硬性规定），通常包名和目录名一致（约定俗成），只有可执行文件可以被命名为 main 包

只有给人跑的代码(可执行文件)，才要用 `main()`，给其他代码 import 的，就不要 `main()`，main 包不能被 import

go run 执行顺序: 依赖包完成初始化 -> 本包变量（按照依赖顺序初始化，不是声明顺序）-> 本包所有 init -> main.main

使用包时，包名以引入路径的最后一段为准（其实是因为那个路径的包一般包名和目录名一致，本质上是包名为准

支持小括号分组导入

go.mod 所在的目录就是模块的根目录，模块只能看到本模块的目录下的包，并进行引入

只有 package main 才能用 go run . 跑起来，（用 go test 跑会创建虚拟 main 包）
一个目录只能有一个 main 包，一个模块可以有多个 main 包（但是要在不同目录下）

每个目录下只能有一个包（除同名 _test 的外部测试包、被 build 约束排除的文件）
一个包可以有任意个文件，这些文件直接不需要互相 import 也无法 import（因为本质是同一个包），所有小写标识符都可以跨文件自由访问，顶层标识符共享一个命名空间，所以不要同一个包名的多个文件声明同名顶层变量，否则会和单文件同名一样，报错重复声明（init 除外，可以有多个，同文件多个 init 按照声明顺序执行，由语言本身保证，跨文件的 init 由编译器确定，go 命令是用文件名字顺序）

引入同一个模块下的其他包，需要从模块根开始，即初始化时的名字(go mod init scope/name)
**模块名 + 相对路径进行 import**

模块下的正常包目录名称不要用下划线、点开头或者名字为 testdata，否则会被忽视，无法引入，子目录自己有 go.mod 也会被忽视

包里面标识符，小写字母开头是私有的，大写字母开头是可以被 import 使用的

**但是 import 是文件级的**，同一个包名的多个文件如果都要使用同一个包，需要各自进行 import
这点可以拆分两层来理解，包的引入本身依旧是在包级别的，每个文件里 import 只是取一个名字，方便直接看到包来源，也方便看到是包是否在使用
**依赖是包级别的，名字是文件级别的**
`import "fmt"` 这句做了两件事
1.给包添加一个依赖（包级，全包共享，`go list -f '{{.Imports}}' .`查看）
2.给本文件绑一个名字（文件级，不外溢）


顶层标识符（函数、类型、变量） 包级别 跨文件自由访问，重名报 redeclared
init 包级别 跨文件累加，全部执行
依赖关系 包级别 go list 看到的是并集
import 绑定的包名  文件级别 每个文件各自 import，别名也是独立的


总结： 一个目录一个包（硬性），目录名和包名一致（约定俗称），依赖关系也是包级（目录），只有命名是文件级（方便开发），

## 标识符

用下划线或者 Unicode 字符开头，内容可以是数字、下划线、Unicode 字符（包括中文，不包扩 emoji），小驼峰命名
单独一个下划线命名，则是空白标识符，能被赋值，不能被读取，也不占用命名空间（可以重复声明多次）用于丢弃返回值
大写字母开头被判断为可以被 import 使用，每一层单独判断（未导出的类型有被导出和未导出的字段）

int len nil true 这些预先声明的标识符，不是保留字，是可以覆盖的

## 函数

返回值可以有多个，还可以命名返回值

命名返回值会被视作在函数顶部声明变量，裸返回会返回这些变量

## 变量

同类型可以连续声明，最后再写类型
不写类型也可以自行推断（是否有范围限制，如果没有那就是可以不写类型了）
var 声明变量不能不写类型也不写值

变量声明之后就一定有确定的值（Go 保证任何变量声明之后立即被零值初始化，没有未初始化内存这个状态）

### 零值

数值类型 (int/float/rune/byte/complex) 0
bool  false
string "" 长度是 0，不是 nil，所以字符串永远可以安全 .len()
指针、slice、map、chan、func、interface  nil
数组 每个元素各自零值 [0, "", nil]
struct 每个字段各自零值 {0 "" nil}

nil slice 和 nil map 都能 len() 和 range （0 次）
nil slice 可读可写
nil map 可读，但是不能直接写，会 panic

### 声明
var a int = 1  完整类型
var b = 2  省类型，推断
var c int  省值，零值
d := 3  短声明，只能在函数内使用，包级必须 var（因为包级只允许声明，而 := 是语句），可以同时声明+赋值多个值，但是左边至少要有一个新的变量（声明）
**不能同时省略类型和值**
局部变量声明了就必须使用，包级可以不用


Go 没有独立的 char 类型，字符字面量就是整数
```go
// 无类型常量各自推断的默认类型
i := 1      // int      （不是 int64，即使在 64 位机器上）
f := 1.0    // float64
r := 'A'    // int32    （rune 是 int32 的别名）
s := "s"    // string
cx := 1+2i  // complex128
```

Go 也没有任何类型隐式转换，所有转换都得显式写出
int 和 int64 不能直接计算，和 float64 不能直接计算
type MyInt int 起了别名也不算同一类型了
var m MyInt = 5
var n int = 4
m + n // mismatched types int and MyInt

s + strconv.Itoa(i)

唯一特殊的是，无类型常量 `const k = 1`,可以把 k 赋值给 int float64 byte rune complex128 
const 在编译期求值，可以无类型，但是只能是 布尔、数值、字符串,局部声明未使用不报错，无类型常量也不能用 := 赋值
有 iota 计数器
常量不占运行时资源，留着没有代价

```go
// 1/2 是整数除法，即使赋值给 float64，也是 0，定型发生在整个表达式算完之后
var f3 flaot64 = 1 / 2 // 先按整数计算出 0，再变成 float 64
var f4 float64 = 1.0 / 2

// string(整数) 被解释为  【Unicode 码点 -> 字符】
n := 65
string(n) // "A"
strconv.Itoa(n) // "65"
````

默认类型只有 6 个：int float64 int32(rune) string bool complex128
默认类型如果装不下这个值，也会报错
`var a = 1 << 100` 不会因为右边值太大就变成 int 64，超出范围直接报错
 int 宽度跟着平台走，要固定宽度就得显式写 int64 (现在大部分平台都是 64 位)

 ```tex
 无类型常量 8  ──推导默认类型──→  int  ──检查是否装得下──→  var i int = 8
    （编译期，任意精度）              （定型）           （运行时确定的类型）
 ```
 编译期就已经完成了定型
 Go 把类型固化进了机器码（不太理解，以后再补）

 连续声明多个不同类型变量，避免写很多 var
 和 import const type 一样的括号合并语法
 var (
    a bool
    b int
    c string
 )

:= 和 var 声明的本质是同一种变量，只是语法层次有区别，没有任何运行时的差异
:= 是 声明+类型推导+初始化的简写，仅在函数内使用，只能推导类型不能显式写类型，且必须有值不会走零值，左边至少有一个新的变量（var 不能用来赋值，也不能作用域重复声明）

int 变量相除结果也是整数（整除，不会隐式改变类型）

## 流程

go 的 if 判断和 for 循环都不需要小括号，但是大括号不能缺少

### 循环

go 只有一种循环语法 `for 初始化语句; 每次迭代前求值的条件表达式; 每次迭代结束后执行的后置语句`

其中初始化语句可以在循环之前初始化，后置语句可以改为放在迭代过程中，所以二者都可以省略（但是要保留对应位置的分号）
二者都省略时就可以连分号一起省略，这样就类似 while 循环了，只剩下一个条件表达式
连条件表达式都省略就是无限循环了 `for {}`

初始化语句声明的变量作用域，1.22 之前，整个循环共用一个变量（所以存在闭包问题），1.22 改成了每次迭代一个新变量

range 作为循环语句时，对不同类型遍历逻辑不同

除了 return 还有什么方法可以中断循环

### 条件控制

`if 可选的前置语句; 条件判断表达式` 前置语句声明的变量，作用域只能持续到 if 语句结束（包括 else 部分）

`switch` 分支可以是数组和 struct, 也可以是表达式（从上往下依次运算并匹配，匹配上之后就不再计算后续的表达式了）
可以连续匹配多个 `case 'a', 'b', 'c':`
可以类型匹配 `switch v:=x.(type)`
可以带有初始化语句，作用域限制在 switch 内
没有条件的 switch 语句，就是匹配 true，效果类似 if/else

**自动 break，不会穿透**

go 没有三元运算符，流程控制的大括号都不能省略

### defer

`defer` 会将函数语句延迟到外围函数返回时执行，但是被延迟调用的参数会立即执行

defer 延迟的调用，会依次压入栈，然后栈出执行（先进后出）
[defer-panic](https://go.dev/blog/defer-panic-and-recover)

**能修改命名返回值，间接修改返回结果？**
不是命名返回值却不会修改返回结果？

带命名返回值的函数，直接返回常量会赋值给命名返回值变量
